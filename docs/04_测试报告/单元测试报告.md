|---|---|---|

**关键设计点**：

| 设计 | 说明 |
|---|---|
| `TESTING` 环境变量 | `os.environ['TESTING'] = 'true'` **在导入 app 之前设置**，使 `database.py` 中的引擎延迟初始化逻辑跳过真实数据库连接（`if _mysql_engine is None and not os.getenv('TESTING')`） |
| `StaticPool` | 内存 SQLite 默认每个连接独立数据库，用 `StaticPool` 强制复用同一连接，保证建表与会话看到同一份内存库 |
| 模型注册 | `from app.models import talent, position, assessment, training, permission` —— 触发 `app/models/__init__.py` 执行，**间接导入 knowledge 模型**，确保 21 张表全部注册到 `Base.metadata` |
| 类型注解兼容 | SQLAlchemy 2.0 类型注解在 SQLite 下与 MySQL 的 Enum/JSON 存在差异，测试层已做适配（既有记录中的已知处理项） |

**结论**：项目内已建立覆盖率配置，执行 `cd backend && pytest` 即产出 `htmlcov/`（HTML）与 `coverage.xml`（CI 可读）。既有材料中"覆盖率 85%"的说法仍**无历史产物可回溯**，但**配置已就位、可随时复现**，验收现场执行一次即可取得落盘证据。当前 `pytest.ini` 内容如下：

```ini
[pytest]
testpaths = tests
python_files = test_*.py
python_classes = Test*
python_functions = test_*
asyncio_mode = auto
asyncio_default_fixture_loop_scope = function
addopts =
    -v
    --tb=short
    --strict-markers
    --cov=app
    --cov-report=term-missing
    --cov-report=html:htmlcov
    --cov-report=xml:coverage.xml
markers =
    slow: 耗时较长的用例（真实 LLM / 外部服务联调）
    integration: 需要真实 MySQL/Redis/Milvus 等外部依赖的用例
filterwarnings =
    ignore::DeprecationWarning:passlib.*
    ignore::DeprecationWarning:jose.*
```

> 说明：`pytest.ini` 默认不设覆盖失败阈值（`--cov-fail-under`），避免首次运行因阈值整体红灯；验收要求 ≥80% 时，在 `addopts` 追加 `--cov-fail-under=80` 即可。
