|---|---|---|

| 测评 | `assessment` | 题库、试卷、任务、结果、雷达图 |
| 培训 | `training` | 课程、计划、学习、考核 |
| 匹配 | `matching` | 匹配、结果、候选人、适配岗位 |

| 知识库 | `knowledge` | 上传、向量化、检索、问答、文件管理 |
| 智能体 | `agents` | 5 个 Agent + NL2SQL + Dify 报告 |

- 统一响应解包：后端返回 `{code, message, data}`，API 层返回 `data`
- TypeScript 类型定义与后端 Pydantic Schema 对齐

### 4.1 关键路径与风险

| 风险项 | 影响 | 缓解措施 |
|---|---|---|
| `AgentCenter`（1035 行，复杂度最高） | 若延误会阻塞 AI 能力演示 | D6 优先启动，提前锁定 Agent 接口契约 |
| `AssessmentList`（993 行） | 测评闭环演示依赖 | D4 集中投入，组卷/评分/雷达图分步验收 |
| 后端接口未就绪 | 前端阻塞 | 约定接口契约后前端先行开发，用 Mock 数据并行 |
| AI 接口响应慢（40–56s） | 前端需处理长等待 | 引入 Loading/骨架屏 + 异步任务轮询（Dify 报告已用 task_id 模式） |
| 权限逻辑不一致 | 越权或功能不可见 | 前端菜单/路由守卫 + 后端接口鉴权双重保障，联调阶段专项核验 |

## 五、权限实现方案

### 5.1 三层前端权限控制

| 层级 | 实现 | 位置 |
|---|---|---|
| **菜单级** | `MENUS` 数组每项声明 `roles`，`hasAnyRole` 过滤，空分组不渲染 | `MainLayout.tsx` |
| **路由级** | 三级守卫：`RequireAuth`（登录）→ `RequireStaff`（staff 角色）→ `RequireRole(role)`（指定角色） | `App.tsx` |
| **接口级** | 由后端 RBAC 强制；前端仅做友好提示 | 后端 |

### 5.2 角色-页面映射（开发依据）

| 角色 | 可见页面 |
|---|---|
| `super_admin` | 全部 12 个页面 |
| `admin` | 除 `/users` 外全部（含 `/agent`、`/skills`） |
| `hr` | `/`、`/talents`、`/positions`、`/assessments`、`/training`、`/matching`、`/knowledge` |
| `user` | `/me`、`/knowledge` |

### 5.3 数据脱敏的前端配合

| 项 | 要求 |
|---|---|
| 不自行脱敏 | 脱敏由后端完成，前端**直接展示**响应值 |
| 不缓存明文 | 前端不存储明文敏感字段 |
| 字段缺失容错 | 薪酬等字段返回 `null` 时正常渲染为"暂无"或留空 |

## 六、质量保障措施

| 措施 | 说明 |
|---|---|
| 类型安全 | TypeScript 严格模式；API 响应类型与后端 Schema 对齐 |
| 组件复用 | 统一弹窗模式（新增/编辑/详情）、统一二次确认、统一分页 |
| 错误处理 | axios 响应拦截统一处理；401 自动跳转登录 |
| 加载体验 | 应用启动恢复登录态显示全屏 `Spin`；AI 长任务使用异步任务 + 轮询 |
| 降级容错 | 后端降级返回（如向量检索为空）时前端展示空态而非报错 |
| 响应式 | 布局弹性 + 表格横向滚动 + 图表容器自适应 |
| 构建验证 | `npm run build` 必须零错误通过 |
| 自测 | 按《前端自测报告》清单逐项验证 |
