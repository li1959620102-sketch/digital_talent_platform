经核查，项目 `docs/` 目录下的 `原型图.png` 实际内容为**技术架构与技术栈示意图**（含前端框架层、Dify AI 中台层、Milvus/Redis/MySQL 数据层、Docker/Ollama 基础设施层等），**并非界面线框图（Wireframe）**。

## 二、信息架构与导航设计

### 2.1 导航分组设计理念

侧边栏**不按功能罗列，而按"人才全生命周期"业务主线**组织为 7 个业务板块：

| 分组 | 分组名称 | 业务定位 | 包含菜单 |
|---|---|---|---|
| `home` | 工作台 | 入口总览 | 全局看板、我的成长 |
| `talent` | 人才盘点 | 建档案 → 摸清队伍 | 人才档案 |
| `evaluate` | 能力评估 | 测评 → 看短板 | 测评管理 |
| `deploy` | 人岗配置 | 匹配 → 用人 | 岗位管理、岗位匹配 |
| `grow` | 培养发展 | 培训 → 补短板 | 培训管理 |
| `ai` | AI 能力 | 平台差异化能力 | 智能知识库、AI 智能体、技能编排 |
| `system` | 系统管理 | 账号与权限 | 用户管理 |

**设计要点**：空分组不渲染；每个菜单项在代码中标注了"它在生命周期里解决什么问题"（`value` 字段），作为板块定位说明。

### 2.3 路由与权限控制（`App.tsx`）

| 路由 | 页面组件 | 守卫级别 | 说明 |
|---|---|---|---|
| `/login` | `Login` | 公开 | 已登录访问时按角色跳转（管理侧→`/`，普通员工→`/me`） |
| `/me` | `MyGrowth` | `RequireAuth` | 员工个人自助工作台，全员可访问 |
| `/` | `Dashboard` | `RequireAuth` + `RequireStaff` | 全局看板 |
| `/talents` | `TalentList` | `RequireAuth` + `RequireStaff` | 人才档案 |
| `/positions` | `PositionList` | `RequireAuth` + `RequireStaff` | 岗位管理 |
| `/assessments` | `AssessmentList` | `RequireAuth` + `RequireStaff` | 测评管理 |
| `/training` | `Training` | `RequireAuth` + `RequireStaff` | 培训管理 |
| `/matching` | `Matching` | `RequireAuth` + `RequireStaff` | 岗位匹配 |
| `/knowledge` | `KnowledgeBase` | `RequireAuth` | 知识库，全员可访问 |
| `/agent` | `AgentCenter` | `RequireAuth` + `RequireRole('admin')` | AI 智能体 |
| `/skills` | `SkillsDesigner` | `RequireAuth` + `RequireRole('admin')` | 技能编排 |
| `/users` | `UserList` | `RequireAuth` + `RequireRole('super_admin')` | 用户管理 |
| `*` | — | — | 兜底：`Navigate to="/"` |

**三级守卫设计**：

| 守卫 | 逻辑 | 未通过时行为 |
|---|---|---|
| `RequireAuth` | 检查登录态（`loading` 期间显示全屏 `Spin`） | 跳转 `/login`（带 `state.from` 记录来源路径） |
| `RequireStaff` | 角色含 `super_admin` / `admin` / `hr` | 跳转 `/me`（普通用户落到个人工作台，不白屏） |
| `RequireRole(role)` | `hasRole(role)` | 跳转 `/`（避免白屏） |

**关键交互设计**：路由收敛为**单一 `MainLayout` + `Outlet`** 结构，保证路由切换时 Sider 实例与 DOM 稳定，避免侧边栏重渲染导致的滚动位置丢失。

## 三、页面交互详细说明

### 3.1 登录页 `/login`（Login.tsx，942 行）

**页面构成**：`Form` × 25 处使用；`Tabs` × 1

**核心交互**：
| 要素 | 说明 |
|---|---|
| 品牌展示区 | 平台名称「数智人才平台」+ 品牌副标题「DIGITAL · TALENT」+ 脑图标 LOGO（青色/紫色渐变） |
| 能力特性展示 | 4 项能力标签：**智能解析 / AI 匹配 / 测评分析 / 决策驾驶舱** |
| 登录表单 | 用户名 + 密码；提交调用 `POST /api/v1/auth/login` |
| 登录成功 | 按角色分流：管理侧（含 admin/hr/超管）→ `/`；普通用户 → `/me` |
| 登录失败 | 展示后端返回的 `message`（如账号锁定提示） |

**设计要点**：登录页为平台"门面"，承担能力宣示作用；表单校验与错误提示走 antd 统一反馈。

### 3.3 人才档案 `/talents`（TalentList.tsx，379 行）

**页面构成**：`Table` × 2、`Form` × 22、`Descriptions` × 29、`Modal` × 7、`Select` × 6、`Tag` × 5、`Card` × 5

**交互流程**：

| 操作 | 触发 | 交互 | 接口 |
|---|---|---|---|
| 列表浏览 | 页面加载 | 分页表格，展示姓名、学历、状态、部门、经验年限等 | `GET /talents` |
| 查看详情 | 点击行/操作按钮 | **Modal「人才档案详情」**，用 `Descriptions` 展示全字段（教育背景、工作经历、技能证书、期望薪资、标签、画像） | `GET /talents/{id}` |
| 新增档案 | 点击「新增人才档案」 | **Modal 表单**：姓名、性别、手机号、邮箱、学历、专业、经验年限、当前公司/职位、期望薪资、自我介绍 | `POST /talents` |
| 编辑 | 行操作 | 复用表单 Modal | `PUT /talents/{id}` |
| 删除 | 行操作 | **二次确认 Modal「确定删除该人才档案？」** | `DELETE /talents/{id}` |
| 条件筛选 | 搜索区 | 按姓名、学历、状态、部门、经验年限区间筛选 | `GET /talents` 参数 |
| 简历解析 | 上传入口 | 上传 PDF/Word/图片 → 自动解析建档 | `POST /talents/parse-resume` |
| 批量导入 | 上传入口 | 上传 Excel/CSV → 返回迁移报告 | `POST /talents/batch-import` |

**状态标签（4 种，实测）**：`在岗`（active）/ `储备`（reserve）/ `休假`（on_leave）/ `离职`（resigned）

**新增人才表单实际字段（实测）**：姓名、工作年限、学历、当前职位、当前公司

**脱敏展示**：若无字段级权限，手机号显示为 `138****0007`，身份证/住址打码，期望薪资显示为空。

## 七、交互设计的一致性约定

| 约定 | 说明 |
|---|---|
| 弹窗优先 | 新增/编辑/详情统一使用 `Modal`，避免页面跳转丢失列表上下文 |
| 二次确认 | 所有删除操作必须二次确认 |
| 分页统一 | 列表接口统一 `page` / `page_size` 参数（`page_size` 上限 100） |
| 权限前置 | 菜单按角色隐藏 + 路由守卫拦截 + 后端接口鉴权，三重防护 |
| 脱敏不提示 | 无权限字段静默脱敏（不打码提示），避免泄露字段存在性 |
| 降级不白屏 | 守卫失败重定向至友好页面，不出现空白页 |
