# 知识库（RAG）管理与智能问答最佳实践

> 版本：v1.0 · 更新日期：2026-09 · 适用角色：admin / hr / 内容维护者

## 一、知识库能做什么

平台知识库基于 **RAG（检索增强生成）** 架构，把 HR 文档（制度、手册、FAQ、JD、培训材料）向量化后，让 AI 能"读过你的文档再回答"：

| 典型场景 | 示例提问 |
|---------|---------|
| 制度问答 | "新员工入职需要准备哪些材料？" |
| 岗位说明 | "高级后端工程师的技能要求和晋升条件？" |
| 培训查询 | "P6 级工程师 Q3 推荐培训课程有哪些？" |
| 流程查询 | "试用期转正的流程和审批节点？" |
| 政策解读 | "公司年假规则是怎样的，未休怎么办？" |

## 二、架构与数据流

```
上传文件（PDF/Word/MD/TXT/Excel）
  ↓  MinIO 存储桶：knowledge-docs（原始文件）
解析文件文本（pdfplumber / python-docx / openpyxl）
  ↓  本地临时文件 → 处理完自动删除
按 ChunkingStrategy 切片（默认 Jieba + 段落边界，chunk_size=512，overlap=64）
  ↓
Embedding 向量化：bge-m3:latest → 1024 维
  ↓
存入 Milvus：knowledge_base 集合（schema: id, file_id, text, vector, metadata JSON）
  ↓
用户提问 → 问题 embedding → Milvus ANN 搜索 top_k=5 → 拼入 Prompt
  ↓
LLM 生成答案 + 引用片段 + 来源文件
```

## 三、支持的文件类型

| 格式 | 扩展名 | 解析方式 | 限制 |
|------|--------|---------|------|
| Markdown | `.md` | 纯文本 + 按标题切分 | 推荐优先使用 |
| 纯文本 | `.txt` | 同上 | ≤ 20MB |
| Word | `.docx` | python-docx 提取段落/表格 | 不支持 .doc 老格式 |
| PDF | `.pdf` | pdfplumber（文字层） | 扫描件/OCR 暂不支持 |
| Excel | `.xlsx` | openpyxl 逐行 + 表头注入 | 每个 sheet 单独切片 |
| CSV | `.csv` | 同上 | UTF-8 编码 |

> ⚠️ 大于 50MB 的文件请拆分后上传，或联系管理员调整 `.env` 中 `MAX_UPLOAD_SIZE`。

## 四、文件管理操作（知识库页面）

### 4.1 上传文件
1. 进入「知识库 → 知识文件」→ 点击 **上传文件**
2. 选择本地文件（可多选），可选填写 **分类标签**（如 制度、培训、岗位）
3. 点击上传 → 状态从「处理中 → 已向量化」完成
4. 失败则状态显示「失败」，鼠标悬浮查看失败原因

### 4.2 查看与删除
- 列表列：文件编号 / 文件名 / 分类 / 大小 / 状态 / 上传时间 / 操作
- 操作 1：**预览** — 查看切片前的原始文本
- 操作 2：**重新向量化** — 修复 embedding 失败时使用
- 操作 3：**删除** — 同时删除 Milvus 中该 file_id 的所有向量 chunk，**不可恢复**

### 4.3 失败状态处理清单
| 失败标识 | 常见原因 | 修复 |
|---------|---------|------|
| PARSER_ERR | 不支持的扩展名 / 文件损坏 | 转成 docx 或 md 后重传 |
| EMBEDDING_TIMEOUT | Ollama 未启动 / bge-m3 未拉取 | `ollama pull bge-m3:latest` 后重试 |
| MILVUS_INSERT_ERR | Milvus 挂了 / collection 不存在 | 重启 Milvus；执行 `app/core/milvus_client.py create_collection` |
| MINIO_UPLOAD_ERR | MinIO 端口不对 / bucket 不存在 | 检查 9100 端口 + 手动创建 `knowledge-docs` bucket |

## 五、智能问答使用技巧

### 5.1 提问好姿势
✅ 好问题（完整句子 + 上下文）：
- "新入职的应届毕业生办理入职需要准备哪些证件和材料？"
- "请列出 P6 级别的高级后端工程师晋升到 P7 需要满足的核心条件"

❌ 坏问题（关键词过短 / 歧义）：
- "入职？"
- "P7 P6 区别"
- "材料"

### 5.2 答案引用
回答下方会列出 **引用片段**（原文中最相关的 2~3 段），每段标注：
- **来源文件名**（点击可打开预览）
- **相似度得分**（越高越相关，≥ 0.6 为高置信）
- **原始段落**（AI 回答的"证据"）

如果答案与引用冲突，请以引用原文为准——AI 可能"过度发挥"。

## 六、Chunk 与 Embedding 调优

> 一般用户不需要调整，以下针对内容管理员

### 6.1 切片参数
```
chunk_size = 512 tokens ≈ 380 汉字
chunk_overlap = 64 tokens ≈ 48 汉字
分隔符：按换行 + 句子边界（Jieba 分词不拆词）
```
- 文档短（< 5 页）：保持默认
- 文档长（> 30 页 且 结构性强）：切 `chunk_size=384`，检索命中率更高
- 代码 / 配置文档：切 `chunk_size=768, overlap=192`，避免函数被拆断

### 6.2 检索参数
| 参数 | 默认 | 调整建议 |
|------|------|---------|
| top_k | 5 | 答案不完整 → 调大到 8；回答太杂 → 调小到 3 |
| threshold | 0.3 | 答非所问 → 调到 0.5；召回太少 → 调到 0.2 |
| rerank_enable | False | 有条件开 bge-reranker，准确率提升 10%~20% |

### 6.3 提高命中率的内容编写建议
1. **标题层级清晰**：`# 一级 / ## 二级 / ### 三级`，AI 会把标题注入每个 chunk 的 metadata
2. **FAQ 列表化**：用 `### Q: 问题？` + `### A: 回答` 的格式，每个 Q&A 独立成段
3. **避免表格里嵌复杂文字**：关键规则在表格下方用文字再解释一遍
4. **术语首次出现写全称**："KPI（关键绩效指标）"，避免向量理解歧义
5. **定期重入向量**：文档大改后点「重新向量化」，否则 AI 仍基于旧版本回答

## 七、故障排查速查

| 现象 | 排查 1 | 排查 2 | 排查 3 |
|------|--------|--------|--------|
| 所有回答"知识库中未找到相关内容" | 文件状态是否都是「已向量化」 | 检查 Milvus knowledge_base 集合 record数 > 0 | Ollama bge-m3 是否拉取 |
| 回答驴唇不对马嘴 | 提问改成完整句子，重问 | 调高 threshold 到 0.5 | 检查切片是否过大，缩小 chunk_size |
| 回答正确但与事实冲突 | 打开引用片段，比对原文 | 重向量化对应文件 | 补充反例文档，让 RAG 自己取舍 |
| 上传文件 413 Payload Too Large | 调大 Nginx `client_max_body_size` | 调大 `.env` 的 `MAX_UPLOAD_SIZE` | 拆分文件后重传 |
| 中文问答全是乱码 | 确认 embedding 时 text 是 UTF-8，非 GBK | 文档另存为 UTF-8 后重传 | 检查 MinIO 下载返回编码头 |
