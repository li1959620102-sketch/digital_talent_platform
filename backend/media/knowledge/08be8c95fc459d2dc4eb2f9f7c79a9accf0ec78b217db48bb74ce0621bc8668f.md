# 岗位匹配算法原理与调优手册

> 版本：v2.0 · 更新日期：2026-10-13 · 适用角色：admin / 算法负责人
>
> **修订说明**：v1.0 描述的权重（学历 5 分 / 技能 60 分 / 向量 25 分、五阶段含向量融合）与
> `app/api/v1/matching.py` 的实际实现不符，会误导调优与验收核对。本版依据**源码实测**重写，
> 并在第六章保留差异对照供回溯。

## 一、算法概述

岗位匹配（Matching）模块采用 **「学历硬门槛 → 经验评分 → 技能重叠 → 经验加成」** 的四步加权模型，
输出每个岗位的 TopN 人才推荐列表及匹配分（0–100）。

```
输入: position_id + top_n
    ↓
[Step1] 学历门槛（权重 30）—— 不满足直接返回 0 分，不进入后续计算
    ↓
[Step2] 经验评分（权重 25）—— 满足得满分；不足按比例给分
    ↓
[Step3] 技能重叠（权重 45）—— 按技能覆盖率线性计分
    ↓
[Step4] 经验加成（上限 10）—— min(10, 工作年限 × 0.3)
    ↓
输出: score = min(100, 总分)  + strengths / weaknesses / reasons
```

> ⚠️ **重要口径**：当前实现**没有向量相似度融合阶段**。岗位匹配完全基于结构化字段
> （学历 / 经验年限 / 技能集合）计算，不调用 Milvus 做语义相似度加权。
> Milvus 向量检索用于**人才语义搜索**（`POST /positions/search`、`POST /talents/search`），
> 与匹配打分是两条独立链路。

## 二、各步骤详解

### 2.1 Step1 学历门槛（30 分，硬门槛）

```python
EDU_ORDER = ["高中", "大专", "本科", "硕士", "博士"]
talent_edu_idx = EDU_ORDER.index(talent.education)   # 非标准值返回 len(EDU_ORDER)
req_edu_idx    = EDU_ORDER.index(position.education_requirement)

if talent_edu_idx >= req_edu_idx:
    score += 30          # 达标加分
else:
    return {"score": 0.0, ...}   # 不达标直接 0 分，不再计算后续
```

> ⚠️ **排查提示**：匹配结果为 0 分时，**首先检查人才学历是否低于岗位要求**。这是硬门槛。
>
> ⚠️ **不可配置**：学历门槛当前**无法通过参数关闭**（无 `hard_filter_enable` 开关），
> 需要软性匹配必须改代码。

### 2.2 Step2 经验评分（25 分）

```python
req_exp, talent_exp = position.experience_requirement or 0, talent.experience_years or 0

if req_exp > 0:
    if talent_exp >= req_exp:
        score += 25                                       # 满足即满分
    elif talent_exp > 0:
        score += round(25 * (talent_exp / req_exp), 1)     # 不足按比例
else:
    score += 25                                           # 岗位无经验要求 → 满分
```

例：要求 3 年、人才 2 年 → 25 × (2/3) = 16.7 分。

### 2.3 Step3 技能重叠（45 分，权重最高）

```python
# 技能集构建：兼容 ["Python"] 与 [{"name": "Python"}] 两种元素格式，大小写与空白归一
overlap = req_skills_lower ∩ talent_skills

if req_skills:
    score += 45 * (len(overlap) / len(req_skills))   # 覆盖率线性计分
else:
    score += 45                                      # 岗位无技能要求 → 满分
```

**优势 strengths** = 岗位要求 ∩ 人才技能（最多列 3 个）
**短板 weaknesses** = 岗位要求 − 人才技能（最多列 3 个）

> 💡 **数据质量关键点**：`talents.skills_certificates` 与 `job_positions.skill_requirements`
> 必须是**标准 JSON 数组**。若库中存为 Python 字面量字符串（单引号，如 `['Java','Spring']`），
> 技能匹配将永远失败，表现为「所有人匹配分偏低且短板=整份技能列表」。
> 修复示例：`UPDATE job_positions SET skill_requirements = JSON_ARRAY('Python','SQL') WHERE id = ?`

### 2.4 Step4 经验加成（上限 10 分）

非线性封顶，防止「年限碾压技能」：

```python
if talent_exp > 0 and score > 0:
    score += round(min(10, talent_exp * 0.3), 2)
```

| 工作年限 | 加成 |
|---|---|
| 1 年 | +0.3 |
| 3 年 | +0.9 |
| 10 年 | +3.0 |
| 33 年 | +9.9 |
| ≥ 34 年 | +10（封顶） |

### 2.5 归一与截断

```python
score = round(min(100.0, score), 2)
```

三项权重合计 30 + 25 + 45 = 100，加上经验加成后可能超过 100，故 `min(100, ...)` 封顶。

## 三、典型匹配分参考区间

| 总分 | 含义 | 建议操作 |
|------|------|---------|
| ≥ 85 | 高度匹配 | 直接推荐面试（Golden 判定为「相关」） |
| 70 ~ 84 | 较匹配 | 推荐初筛，评估短板是否可通过培训补齐 |
| 55 ~ 69 | 弱匹配 | 人才池储备，不推当前岗 |
| < 55 | 不匹配 | 不进入推荐列表 |

**Golden 回归测试**（`tests/golden_dataset.json`）内置 **14 条** case（M01–M14）。
判定口径：学历达标 **且** 经验达标 **且** 命中 ≥2/3 必备技能 → 相关；`match_score >= 85` 判相关。
每次改动须跑通：`pytest tests/test_golden_match.py -q`（当前 **14/14 = 100%**）。

## 四、调优参数速查（均位于 `app/api/v1/matching.py` 的 `compute_match_score`）

| 参数 | 代码位置 | 当前值 | 调大影响 | 调小影响 |
|------|---------|--------|---------|---------|
| 学历权重 | Step1 | **30** | 学历更关键（且是硬门槛） | 学历影响降低 |
| 经验权重 | Step2 | **25** | 经验影响提升 | 经验影响降低 |
| 技能权重 | Step3 | **45** | 技能更敏感 | 学历经验比重更大 |
| 经验加成系数 | Step4 | **0.3** | 老员工优势放大 | 老员工优势缩小 |
| 经验加成封顶 | Step4 | **10** | 老员工优势上限提高 | 上限降低 |

> ⚠️ 这些数值目前是**代码内联常量**，不是可配置参数。调整需改代码并重新跑 Golden 回归。

调优建议：
1. 先跑 `pytest tests/test_golden_match.py -q` 确认基线为 14/14
2. 观察 Top10 的 `match_score` 分布（标准差太小 → 需放大技能或经验权重）
3. 改参数后 Golden 回归仍须 ≥ 85%（工程目标 ≥ 90%）才可发布
4. 改代码时保留旧值注释并写明原因，便于回滚

## 五、常见异常与处理

| 异常 | 根因 | 解决 |
|------|------|------|
| 匹配分全部一样或偏低 | `skill_requirements` 格式异常（技能集为空） | 修复列值为合法 JSON 数组 |
| 匹配分全部为 0 | 人才学历低于岗位要求（硬门槛），或经验为 0 且岗位要求经验 | 检查 `education` 与 `experience_years` 字段值 |
| 触发匹配返回 500 | `skill_requirements` 为 dict 列表导致 `unhashable type: 'dict'` | 代码已加 dict 兼容处理；如仍报错需重启后端（清 `__pycache__`） |
| Top 匹配结果集中同一人 | 人才池规模过小，或技能字段大面积缺失 | 补充人才数据；补全技能字段 |
| 高学历与达标学历拉不开差距 | 学历仅作「门槛 + 固定 30 分」，超出不额外加成分 | 如需学历梯度，需新增分级加分逻辑 |

## 六、与 v1.0 版本的差异对照（留痕）

| 项 | v1.0 描述（**错误**） | v2.0 实测（**正确**） |
|---|---|---|
| 学历 | 达标 +5 分 | **+30 分，且为硬门槛（不达标归零）** |
| 经验 | 未单列 | **+25 分，不足按比例** |
| 技能 | 60 × 覆盖率 | **45 × 覆盖率** |
| 向量相似度 | Stage4，25 分（`max(0,sim) × 25`） | **不存在此阶段** |
| 经验加分 | `min(10, 超出年限 × 0.3)` | `min(10, 工作年限 × 0.3)`（按总年限） |
| 硬过滤开关 | `hard_filter_enable = True` 可配 | **无此开关，门槛写死在代码中** |
| 参数可配置性 | 6 个可调参数表 | **均为代码内联常量** |
