# 岗位匹配算法原理与调优手册

> 版本：v1.0 · 更新日期：2026-09 · 适用角色：admin / 算法负责人

## 一、算法概述

岗位匹配（Matching）模块采用 **"硬条件过滤 → 技能重叠打分 → 学历经验加权 → 向量相似度融合 → 排序截断"** 的五阶段流水线，输出每个岗位的 TopN 人才推荐列表及匹配分。

```
输入: position_id + top_n
    ↓
[Stage1] 硬过滤: 学历 + 经验 + 状态(active/reserve)
    ↓  候选集从 N 缩小到 M
[Stage2] 技能重叠: Jaccard(岗位必备技能 ∩ 人才技能) × 基础权重
    ↓  skill_match_score [0, 60]
[Stage3] 学历经验加分: 学历达标+5、经验超基准加分 min(10, 年限×0.3)
    ↓  bonus_score [0, 15]
[Stage4] 向量相似度: Milvus 检索 (人才简历向量 · 岗位 JD 向量)
    ↓  vector_score [0, 25]
[Stage5] 总和: 0~100 归一化 → 按 match_score 降序取 TopN
    ↓
输出: [{talent_id, name, match_score, strengths, weaknesses, reason}...]
```

## 二、各阶段详解

### 2.1 Stage1 硬性条件过滤
```python
# 伪代码（摘自 app/api/v1/matching.py compute_match_score）
hard_pass = True
if position.education_requirement and talent.education.enum_value < pos_edu_value:
    hard_pass = False
if position.experience_requirement and (talent.experience_years or 0) < position.experience_requirement:
    hard_pass = False
if talent.status not in (ACTIVE, RESERVE):
    hard_pass = False
if not hard_pass:
    return {"score": 0, "strengths": [], "weaknesses": ["学历/经验不满足硬条件"], ...}
```
> ⚠️ 注意：**不满足硬条件直接 0 分，不进入后续计算**，因此匹配结果为 0 分时先检查该人才学历是否低于岗位要求。

### 2.2 Stage2 技能重叠分（核心 60 分）
计算岗位必备技能集合 `P_skills` 与人才技能集合 `T_skills` 的匹配度：
```
命中技能数 = |P ∩ T|
覆盖率 = 命中技能数 / |P|
技能分 = 60 × min(1, 覆盖率)
```

**优势 strengths** = P ∩ T（都命中的技能）
**短板 weaknesses** = P - T（岗位要求但人才缺失的技能）

> 💡 数据质量关键点：`talent.skills_certificates` 和 `position.skill_requirements` 必须为标准 JSON 数组或 dict。若数据库中是 Python 字面量字符串（如 `['Java','Spring']`，单引号），会导致技能匹配永远失败，表现为「所有人匹配分 0~55 且短板=整份技能列表」——可用 `SET skill_requirements = JSON_ARRAY(...)` 修复。

### 2.3 Stage3 学历与经验加分（15 分上限）
```python
# 学历加分
if talent.education ≥ position.education_requirement:
    score += 5  # 刚好达标给 5 分，超过不多加（避免博士碾压本科岗）

# 经验加分（非线性，封顶防止年限碾压技能）
extra_years = max(0, talent_exp - pos_exp_requirement)
if extra_years > 0:
    exp_bonus = round(min(10, extra_years * 0.3), 2)
    score += exp_bonus
# 例：刚好达标: +0；超2年: +0.6；超5年: +1.5；超33年+: +10（封顶）
```

### 2.4 Stage4 向量相似度（25 分）
通过 Milvus 向量库 `talent_resume` 集合检索岗位 JD 向量，获得余弦相似度 `sim ∈ [-1, 1]`：
```python
vector_score = round(max(0, sim) * 25, 2)
```
> 作用：当技能结构化数据稀疏时（新员工技能字段为空），向量语义仍能给出相似度，避免匹配分全部塌陷为相同值。

### 2.5 Stage5 归一化与排序
三项相加后总分数域 `[0, 100]`，按 `match_score` 降序取 TopN，同分则按经验年限、向量得分二级排序。

## 三、典型匹配分参考区间

| 总分 | 含义 | 建议操作 |
|------|------|---------|
| ≥ 85 | 高度匹配 | 直接推荐面试，匹配结果列为「相关」 |
| 70 ~ 84 | 较匹配 | 推荐初筛，评估短板是否可通过培训补齐 |
| 55 ~ 69 | 弱匹配 | 人才池储备，不推当前岗 |
| < 55 | 不匹配 | 不进入推荐列表 |

**Golden 回归测试（tests/golden_dataset.json）** 内置 14 条 case，阈值 85 判相关，每次代码改动必须 `pytest tests/test_golden_match.py -q` 全通过。

## 四、调优参数速查（app/api/v1/matching.py）

| 参数 | 当前值 | 作用 | 调大影响 | 调小影响 |
|------|--------|------|---------|---------|
| skill_weight | 60 | 技能匹配基础分 | 技能更敏感 | 学历经验比重更大 |
| edu_bonus | 5 | 学历达标奖励 | 学历成为门槛 | 学历影响降低 |
| exp_bonus_factor | 0.3 | 经验年限系数 | 年限影响大 | 年限影响小 |
| exp_bonus_max | 10 | 经验加分封顶 | 老员工优势放大 | 老员工优势缩小 |
| vector_weight | 25 | 向量相似度权重 | 语义匹配重要 | 结构化数据更重要 |
| hard_filter_enable | True | 是否开启硬过滤 | 0 分样本减少但精度下降 | 全部样本进入打分 |

调优建议：
1. 先用 `python -m backend.app.api.v1.matching` 本地跑一遍所有岗位匹配
2. 看 Top10 的 match_score 分布（标准差太小 → 需放大技能或向量权重）
3. 再对照 Golden 数据集验证相关样本是否 ≥ 阈值
4. 改参数前先注释旧值并写修改原因，方便回滚

## 五、常见异常与处理

| 异常 | 根因 | 解决 |
|------|------|------|
| 匹配分全部 55 或全部一样 | `skill_requirements` 格式异常，Stage2 技能集为 {} 或 Stage4 向量未生成 | 修复列值为合法 JSON；检查 Milvus `talent_resume` 集合是否有该人才 ID |
| 点击触发匹配返回 500 | `skill_requirements` 为 dict 列表导致 `unhashable type: 'dict'` | matching.py 已加 dict 兼容处理，如仍报错需重启后端（清除 __pycache__） |
| Top 10 匹配结果大部分是同一人 | Milvus 中该人才向量异常，或人才池规模过小 | 重建 `talent_resume` 集合向量；补充人才数据 |
| 博士/硕士与本科岗匹配分拉不开 | edu_bonus 给的是「达标奖励」，超过的学历不再加分 | 如需学历梯度，新增 `edu_level_diff_bonus` 逻辑 |
